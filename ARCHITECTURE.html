📋 System Architecture Overview

🔄 Data Flow

  1. User Interaction: Patients interact with the React frontend through a chat interface or dashboard
  2. Authentication: Users authenticate via JWT tokens through FastAPI auth endpoints
  3. Conversation Flow:
    • User sends a message → FastAPI receives it
    • FastAPI invokes LangGraph agent with conversation state
    • Agent uses LLM (GPT-4o mini) to understand intent
    • Agent calls appropriate tools (extract, verify, create ticket, etc.)
    • Tools interact with PostgreSQL database
    • Agent generates response and returns to user
  4. State Management: LangGraph maintains conversation state, patient verification status, and collected information
  5. Persistence: All conversations, messages, tickets, and patient data are stored in PostgreSQL

🔧 Key Components

Frontend

React + TypeScript + Tailwind CSS for responsive UI with real-time chat interface

Backend

FastAPI with async/await for high-performance API endpoints and WebSocket support

AI Agent

LangGraph StateGraph orchestrates multi-step conversations with tool calling

LLM

OpenAI GPT-4o mini for natural language understanding and generation

Database

PostgreSQL with SQLAlchemy ORM for data persistence and relationships

Tools

Specialized LangChain tools for patient verification, ticket creation, and appointment scheduling

🛠️ Agent Tools

  • extract_patient_info: Uses LLM to extract name, phone, and DOB from natural language
  • verify_patient: Queries database to verify patient identity
  • create_patient: Creates new patient record if not found
  • get_patient_history: Retrieves patient's medical history
  • create_ticket: Creates service tickets (blood tests, consultations, etc.)
  • schedule_appointment: Schedules appointments with doctors

📊 Database Schema

  • patients: Patient information, medical history, blood group
  • conversations: Conversation sessions with status tracking
  • messages: Individual messages in conversations
  • tickets: Service requests with priority and assignment
  • patient_history: Historical medical records
  • appointments: Scheduled appointments with service persons

🔐 Security & Authentication

  • JWT-based authentication for patients, service persons, and admins
  • Password hashing using passlib with bcrypt
  • CORS configuration for frontend-backend communication
  • Patient verification through multi-factor matching (phone, name, DOB)
